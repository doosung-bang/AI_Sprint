1부딥러닝이 대체 뭘 하는 건가

비유

국을 끓이는데 소금을 얼마나 넣어야 할지 모릅니다. 방법은 하나입니다. 조금 넣고 → 맛보고 → 짜면 덜 넣고, 싱거우면 더 넣고. 이걸 계속 반복하면 언젠가 딱 맞습니다.

딥러닝이 하는 게 정확히 이겁니다. 「소금의 양」이 가중치이고, 「맛보기」가 손실 계산이고, 「얼마나 더 넣을지」가 학습률입니다.

컴퓨터에게 「고양이 사진을 알아봐라」라고 시킬 때, 우리는 규칙을 알려주지 않습니다. 대신 숫자 수십만 개를 아무렇게나 놓고 시작해서, 틀릴 때마다 조금씩 고치게 합니다. 그 숫자들이 가중치입니다.

딥러닝의 전부
① 지금 값으로 답을 내본다 → ② 정답과 얼마나 다른지 잰다 → ③ 그 차이를 줄이는 방향으로 값을 조금 옮긴다 → ①로 돌아간다
이 세 줄이 전부입니다. 앞으로 나오는 모든 용어는 이 셋 중 하나를 부르는 이름입니다. ①=순전파, ②=손실함수, ③=역전파+옵티마이저.

2부텐서 — 숫자를 담는 그릇

텐서(tensor)는 어렵게 생긴 이름이지만 뜻은 단순합니다. 「숫자를 규칙적으로 담은 상자」입니다. 엑셀 표를 떠올리면 거의 맞습니다.

shape 읽는 법 — 이것만 익히면 절반은 끝납니다

shape은 「각 방향으로 몇 개인가」를 바깥부터 순서대로 적은 것입니다.

shape (3, 4) 를 읽으면

「줄이 3개, 각 줄에 숫자가 4개」 → 총 12개. 엑셀로 치면 3행 4열입니다.

shape (2, 3, 4) 는 「(3,4)짜리 표가 2장」 → 총 24개입니다.

⚠️ 초보가 가장 많이 헷갈리는 것 — (3,) 와 (3,1) 은 다릅니다

(3,) 는 숫자 3개가 한 줄로 늘어선 것입니다. [7, 9, 4]

(3,1) 은 줄이 3개인데 각 줄에 숫자가 1개입니다. [[7], [9], [4]]

담긴 숫자는 똑같이 3개인데 모양이 다릅니다. 그리고 이 차이 때문에 계산 결과가 통째로 달라집니다 — 4부에서 실제 사례를 보여드립니다.

텐서 만드는 함수들

torch.arange(n)0부터 n-1까지 순서대로
⚠️ 기본이 정수입니다		arange(6) → [0,1,2,3,4,5]

torch.linspace(0,1,100)0부터 1까지 100등분그래프 x축 만들 때

dtype — 숫자의 「종류」

같은 3이라도 컴퓨터는 정수 3과 소수 3.0을 다르게 저장합니다. 그 종류를 dtype이라고 합니다.

dtype뜻어디에 쓰나
torch.float32소수 (기본)딥러닝의 거의 모든 계산. 미분이 되려면 소수여야 합니다
torch.int64 (long)정수정답 라벨 (0번 고양이 / 1번 개). 「몇 번째」는 소수일 수 없으니까
torch.bool참/거짓조건으로 걸러낼 때
여기서 미션 4 「기초 1」이 걸립니다

torch.arange(12)는 정수를 만듭니다. 그런데 확인 셀은 float32를 요구합니다. 모양은 맞는데 dtype에서 떨어지는 이유가 이것입니다.

바꾸는 방법은 두 가지 — 만들 때 지정하거나, 만든 뒤 .float()로 바꾸거나.

3부모양(shape) 바꾸기

딥러닝 코드에서 오류의 절반 이상이 「모양이 안 맞는다」입니다. 그래서 모양을 바꾸는 함수를 따로 익힙니다.

비유

사탕 12개가 있습니다. 개수는 그대로 두고 담는 방식만 바꿀 수 있습니다 — 3개짜리 봉지 4개, 4개짜리 봉지 3개, 2×6 상자… 이게 reshape입니다.

다만 12개를 5개씩 나눌 수는 없습니다. 총 개수가 안 맞으면 오류가 납니다.

reshape — 총 개수를 유지하며 다시 담기

# 12개를 (3,4)로 → 다시 (2,6)으로
t = torch.arange(12)        # shape (12,)
t.reshape(3, 4)             # shape (3,4)  — 3×4 = 12 ✓
t.reshape(2, 6)             # shape (2,6)  — 2×6 = 12 ✓
t.reshape(5, 3)             # ✗ 오류! 5×3 = 15 ≠ 12
t.reshape(-1, 4)            # -1은 «알아서 계산해» → (3,4)
-1의 뜻

「나머지는 네가 계산해」입니다. 12개를 4개씩 담으라면 자동으로 3줄이 됩니다. 데이터 개수가 매번 달라지는 실전에서 아주 많이 씁니다.

squeeze / unsqueeze — 「1짜리 차원」을 없애고 만들기

가장 헷갈리는 둘입니다. 뜻만 잡으면 쉽습니다.

함수하는 일예주의
.squeeze()크기 1인 차원을 전부 없앰(3,1,4) → (3,4)
(1,5,1) → (5,)		전부입니다. 하나만 없애려면 .squeeze(1)처럼 자리를 지정
.unsqueeze(d)d번 자리에 크기 1인 차원을 하나 끼움(3,4) → unsqueeze(0) → (1,3,4)
(3,4) → unsqueeze(2) → (3,4,1)		맨 뒤에 붙이려면 -1을 써도 됩니다
.flatten()전부 한 줄로 폄(3,1,4) → (12,)모델 마지막에 자주 씀
.reshape(a,b)총 개수 유지하고 다시 담기(12,) → (3,4)곱해서 원래 개수가 돼야 함

cat 과 stack — 붙이는 방법이 두 가지

이 둘의 차이가 미션 4 「기초 5」의 핵심입니다.

외우는 법

cat은 「이어붙이기(concatenate)」 — 종이 두 장을 테이프로 붙여 한 장으로 만드는 것.

stack은 「쌓기」 — 종이 두 장을 포개서 두 장짜리 묶음으로 만드는 것. 장수라는 새 개념이 생깁니다.

4부계산 — 브로드캐스팅과 행렬곱

원소별 계산 — 같은 자리끼리

모양이 같은 텐서끼리 + - * /를 하면 같은 자리 숫자끼리 계산합니다. 쉽습니다.

[[1, 2],     [[10, 10],     [[11, 12],
 [3, 4]]  +   [10, 10]]  =   [13, 14]]

브로드캐스팅 — 모양이 달라도 알아서 맞춰준다

모양이 다른데도 계산이 되는 경우가 있습니다. PyTorch가 부족한 쪽을 자동으로 복사해서 늘려주기 때문입니다. 이걸 브로드캐스팅이라고 합니다.

☠️ 조용히 틀리는 사고 — 오류도 안 납니다

모델의 예측값이 (3,1)이고 정답이 (3,)일 때 빼면 어떻게 될까요? 실제로 돌려본 결과입니다.

# 예측 (3,1) — 세로로 선 3개
a = torch.tensor([[1.],[2.],[3.]])
# 정답 (3,) — 가로로 선 3개
b = torch.tensor([10., 20., 30.])

(a - b).shape   → torch.Size([3, 3])   # ← 9개!?
(a - b)
→ [[ -9., -19., -29.],
   [ -8., -18., -28.],
   [ -7., -17., -27.]]

3개를 빼려 했는데 9개가 나왔습니다. 세로 3개 × 가로 3개로 모든 짝이 만들어진 겁니다. 그런데 오류가 안 납니다. 손실 계산까지 그대로 진행되고, 모델은 엉뚱한 걸 학습합니다.

제대로 하려면 모양을 먼저 맞춰야 합니다 — a.squeeze()로 (3,)을 만들면 결과는 [-9., -18., -27.] 3개가 나옵니다.

그래서 습관

계산이 이상하면 먼저 .shape을 찍어 보세요. 「값이 이상하다」의 8할은 「모양이 이상했다」입니다.

행렬곱 — 딥러닝 계산의 심장

* 는 같은 자리끼리 곱하는 것이고, 행렬곱(@ 또는 torch.matmul)은 전혀 다른 계산입니다. 신경망의 층 하나 = 행렬곱 하나입니다.

왜 이 계산을 쓰나

「학생 2명 × 과목 3개 점수」 표에, 「과목 3개 × 대학 4곳 반영비율」 표를 곱하면 → 「학생 2명 × 대학 4곳 환산점수」가 나옵니다. 가운데 「과목 3개」는 계산에 쓰이고 사라집니다.

신경망도 똑같습니다. 입력 특징 개수가 가운데에서 만나 사라지고, 출력 개수가 남습니다.

기호이름하는 일모양
a * b원소별 곱같은 자리끼리 곱함(2,3)*(2,3) → (2,3)
a @ b
torch.matmul(a,b)		행렬곱줄과 칸을 곱해 더함(2,3)@(3,4) → (2,4)
torch.mm(a,b)행렬곱 (2차원 전용)위와 같으나 2차원만(2,3),(3,4) → (2,4)

5부「학습」이란 무엇인가

가장 단순한 모델 — 직선 하나

모든 딥러닝의 출발점은 이 식입니다.

모델의 정체
ŷ = w × x + b
x는 입력(내가 아는 것), ŷ는 예측(내가 알고 싶은 것). w와 b는 컴퓨터가 찾아야 할 숫자입니다. 중학교에서 배운 y = ax + b와 완전히 같은 식입니다.
기호이름중학교 말로뜻
x입력 (input)x값내가 아는 정보. 공부 시간, 사진 픽셀 등
ŷ예측 (prediction)
「와이 햇」이라 읽음		내가 구한 y모델이 내놓은 답
y정답 (target/label)진짜 y실제로 맞는 답
w가중치 (weight)기울기 a학습으로 찾는 숫자. x가 결과에 얼마나 세게 영향을 주나
b편향 (bias)y절편학습으로 찾는 숫자. 전체를 위아래로 옮기는 값

손실(loss) — 「얼마나 틀렸나」를 숫자 하나로

예측이 정답과 얼마나 다른지를 숫자 하나로 만들어야 「나아졌다/나빠졌다」를 판단할 수 있습니다. 그 숫자가 손실입니다.

MSE — 평균제곱오차 (숫자를 맞히는 문제)

실제 계산 과정입니다. 미션 4 「심화 1」에 나오는 바로 그 값입니다.

①②③계산
예측 ŷ2.50.02.0모델이 내놓은 답
정답 y3.0-0.52.0진짜 답
차이 (ŷ-y)-0.5+0.50.0부호가 섞여 있어 그냥 더하면 0이 됨
제곱0.250.250.00제곱하면 부호가 사라지고 큰 오차가 더 커짐

Cross Entropy — 교차 엔트로피 (분류 문제)

「고양이냐 개냐」처럼 고르는 문제에서는 MSE가 아니라 이걸 씁니다. 정답에 얼마나 확신했는가를 재는 방식입니다.

⚠️ 미션 4 「심화 1·4」의 함정

nn.CrossEntropyLoss는 안에 Softmax가 이미 들어 있습니다. 그래서 모델 출력에 Softmax를 또 붙이면 두 번 적용되어 학습이 망가집니다.

정리 — 모델 마지막에는 아무것도 안 붙이고 날것(logits) 그대로 내보냅니다. 정답 라벨은 원-핫이 아니라 정수(0, 1, 2…)여야 합니다.

경사하강법 — 어느 쪽으로 얼마나 옮길까

비유

안개 낀 산에서 눈을 감고 골짜기로 내려가는 것과 같습니다. 앞이 안 보이니, 발밑의 기울기를 더듬어 「내려가는 쪽」으로 한 걸음 옮깁니다. 이걸 반복하면 결국 바닥에 닿습니다.

여기서 「한 걸음의 크기」가 학습률(learning rate)입니다.

직접 해보기 — 학습률을 바꾸면 어떻게 되나

골짜기 모양이 y = x²이고 지금 x = 4에 서 있습니다. 바닥(x=0)까지 내려가야 합니다. 한 걸음의 크기를 바꿔 보세요.

0.10
방금 본 것 정리

너무 작으면 — 방향은 맞는데 너무 조금씩 가서, 정해진 횟수 안에 바닥에 못 닿습니다.

적당하면 — 몇 걸음 만에 바닥에 안착합니다.

너무 크면 — 바닥을 지나쳐 반대편 벽으로 튕겨 올라갑니다. 그리고 더 크게 튕기고, 더 크게… 결국 발산합니다. 손실이 줄기는커녕 폭발합니다.

미션 4 「심화 7」이 묻는 게 이것입니다

SGD를 lr=0.01 / 0.5 / 10.0으로 돌려 비교하라는 문제입니다. 위 실험에서 본 세 가지 상황이 그대로 나옵니다. 답은 직접 돌려서 그래프로 확인하세요 — 여기 있는 건 원리이지 그 문제의 답이 아닙니다.

실제로 학습되는 과정

y = 2x + 1 데이터를 주고 w와 b를 찾게 한 실제 결과입니다. w는 2, b는 1에 가까워져야 정답입니다.

몇 번째w (정답 2)b (정답 1)손실상태

시작할 때 w는 무작위 값이었습니다. 손실이 줄어드는 만큼 w·b가 정답에 가까워지는 게 보입니다.

6부autograd — 미분을 대신 해주는 기계

5부에서 「기울기를 더듬어 내려간다」고 했습니다. 그 기울기를 구하는 게 미분인데, 신경망은 숫자가 수백만 개라 사람이 손으로 못 합니다. PyTorch가 대신 해줍니다. 그 기능이 autograd입니다.

3단계면 끝

# ① 「이 값은 추적해줘」라고 표시
x = torch.tensor(2.0, requires_grad=True)

# ② 계산한다 (PyTorch가 몰래 «어떻게 계산했는지» 기록해 둔다)
y = x**2 + 3*x

# ③ 거꾸로 돌려 기울기를 구한다
y.backward()

x.grad     → tensor(7.)   # dy/dx = 2x+3, x=2 → 7 ✓

☠️ 가장 많이 틀리는 것 — 기울기는 «쌓입니다»

backward()를 부를 때마다 .grad에 덮어쓰는 게 아니라 «더해집니다». 실제로 돌려본 결과입니다.

왜 이렇게 설계했나

「나눠서 계산한 걸 합치고 싶다」는 경우가 있어서 기본이 더하기입니다. 대신 안 쓸 땐 직접 지워야 합니다.

그래서 학습 루프의 첫 줄이 항상 optimizer.zero_grad()입니다. 빼먹으면 손실이 안 줄어드는데 오류는 안 나서 원인을 찾기 어렵습니다.

비슷해 보이는 셋 — no_grad / detach / item

쓰는 법하는 일언제 쓰나
with torch.no_grad():
  ...		이 블록 안에서는 기록을 안 남김가중치를 직접 고칠 때(심화 2), 학습 끝나고 평가할 때. 「고치는 행위」 자체가 학습 대상이 되면 안 되니까
a.detach()그 텐서 하나만 기록에서 떼어냄중간 결과를 다른 데 쓰고 싶은데 학습에 섞이면 안 될 때
a.item()텐서에서 파이썬 숫자 하나를 꺼냄손실값을 기록·출력할 때. losses.append(loss.item())
왜 .item()을 써야 하나

losses.append(loss)처럼 텐서를 그대로 담으면, 그 텐서에 딸린 계산 기록이 통째로 메모리에 남습니다. 수천 번 반복하면 메모리가 꽉 찹니다. .item()은 숫자만 빼옵니다.

7부신경망의 부품들

먼저 — 5부와 7부를 잇는 다리
뉴런 하나 = 5부에서 배운 ŷ = wx + b 그대로입니다. 새로운 게 없습니다.
「신경망」이라는 말 때문에 뭔가 새로운 게 나올 것 같지만, 부품은 이미 다 배웠습니다. 아래 세 걸음이면 82개짜리 MLP까지 이어집니다.

걸음 1. 뉴런 하나 = ŷ = wx + b

입력이 2개면 가중치도 2개일 뿐, 식은 똑같습니다. 입력 x = [5, 4] · 가중치 w = [2, -3] · 편향 b = 1 이면

2×5 + (-3)×4 + 1 = -1

nn.Linear(2, 1) 에 같은 값을 넣어도  -1.0   # 손계산과 정확히 일치

파라미터는 w 2개 + b 1개 = 3개입니다.

걸음 2. 층 = 그 직선을 «여러 개 나란히» 놓은 것

nn.Linear(2, 3) 은 똑같은 계산을 3벌 동시에 하는 것입니다. 같은 입력 [5, 4]를 넣으면:

계산결과
뉴런 12×5 + (−3)×4 + 1−1.0
뉴런 21×5 + 1×4 + 09.0
뉴런 30×5 + 5×4 + (−2)18.0
출력[−1.0, 9.0, 18.0]

뉴런이 3개니까 답도 3개 나옵니다. 그게 nn.Linear(2, 3)의 뒤 숫자입니다.

파라미터 개수 공식이 여기서 나옵니다

위 층의 파라미터 = w 3×2 = 6개 + b 3개 = 9개

파라미터 = 입력수 × 출력수 + 출력수

그래서 미션 4의 82개가 이렇게 나옵니다 — Linear(2,16) = 2×16+16 = 48, Linear(16,2) = 16×2+2 = 34, 합 82.

「16」은 사람이 정한 숫자입니다. 은닉 뉴런을 몇 개 둘지는 정답이 없고, 8이든 32든 됩니다. 미션 4가 16으로 정해준 것뿐입니다.

걸음 3. 활성화 함수가 없으면 층을 쌓아도 «헛수고»입니다

말로 하면 안 믿기니 실제로 돌려 보겠습니다. Linear(2,3) → Linear(3,2) 두 층에 데이터 4개를 통과시킨 결과입니다.

계산은 두 배로 했는데 표현할 수 있는 것은 하나도 안 늘었습니다. 100층을 쌓아도 마찬가지입니다.

활성화 함수 세 가지 — 실제 계산한 곡선
이름모양을 말로출력 범위어디에 쓰나
ReLU음수는 0으로, 양수는 그대로. 꺾인 직선0 ~ ∞층 사이에 가장 많이 씀. 계산이 빠르고 잘 학습됨
